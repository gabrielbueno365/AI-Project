# Fase 4: Inteligência Avançada via Framework de Agentes MCP - Especificação Técnica Revisada

## 1. Visão Geral

Esta fase explora e implementa capacidades avançadas de IA, introduzindo um **Framework de Agentes baseado em LangChain** que opera sobre a arquitetura MCP existente. Os agentes terão acesso às funcionalidades expostas pelos servidores MCP (filesystem, RAG, Ollama NLP, memória, web fetch, etc.) como **Tools**. ### 2.2 Componentes Principais (Atualizado)

1.  **Controlador Principal (Host)**: `core/app.py` + `core/orchestrator.py` (Novo) - O `orchestrator` decide se a consulta vai para o Router (Fase 3) ou para o Framework de Agentes. `app.py` gerencia o ciclo de vida.
2.  **Framework de Agentes (no Host)**: `agents/*.py` - Baseado em LangChain.
    *   `AgentFactory`: Cria instâncias de agentes (Reasoning, Research, etc.).
    *   `Tools`: Wrappers LangChain que usam os **MCP Clients** para chamar as *tools* dos servidores MCP.
    *   Agentes específicos (ex: `ReasoningAgent`) que usam um LLM (via MCP Client para `mcp-server-llm-api` ou `mcp-server-ollama`) para decidir quais Tools MCP chamar.
3.  **Servidor MCP: `mcp-server-metacognition` (Novo/Detalhado)**
    *   **Responsabilidade:** Analisar o raciocínio, verificar fatos, explicar processos.
    *   **Tecnologia:** Python, `FastMCP`, LLM (via `mcp-server-llm-api` ou `mcp-server-ollama`), acesso ao `mcp-server-memory`.
    *   **Interface MCP:**
        *   *Tools:* `reflect_on_reasoning(interaction_ids: list)`, `verify_solution(problem: str, solution: str)`, `explain_thought_process(problem: str, solution: str)`.
4.  **Servidor MCP: `mcp-server-personality` (Novo/Detalhado)**
    *   **Responsabilidade:** Ajustar o tom e estilo das respostas finais.
    *   **Tecnologia:** Python, `FastMCP`, LLM (via `mcp-server-llm-api` ou `mcp-server-ollama`).
    *   **Interface MCP:**
        *   *Tools:* `apply_personality(content: str, personality_type: str, tone: str) -> str`.
5.  **Servidores MCP Existentes (Fases 2 e 3):** Mantidos e agora *também* utilizados pelos Agentes como Tools.

### 2.3 Fluxo de Dados (Exemplo: Tarefa Complexa com Agente)

1.  Usuário digita: "Pesquise as últimas notícias sobre a missão Artemis, resuma os 3 pontos principais e salve em 'artemis_summary.txt'."
2.  **Host (`orchestrator`)** identifica como tarefa complexa e delega para o **Framework de Agentes**.
3.  `AgentFactory` cria um agente de pesquisa/raciocínio.
4.  **Agente (LangChain)**:
    *   **(Pensamento 1):** Preciso buscar notícias sobre Artemis.
    *   **(Ação 1):** Chama a Tool `search_web` (que usa `mcp-server-fetch`).
    *   **(Observação 1):** Recebe resultados da busca (lista de URLs/snippets).
    *   **(Pensamento 2):** Preciso ler o conteúdo das URLs mais relevantes.
    *   **(Ação 2):** Chama a Tool `fetch` (via `mcp-server-fetch`) para 2-3 URLs.
    *   **(Observação 2):** Recebe o conteúdo das páginas em Markdown.
    *   **(Pensamento 3):** Preciso resumir os pontos principais do conteúdo coletado.
    *   **(Ação 3):** Chama um LLM (via `mcp-server-llm-api` ou `ollama`) com o conteúdo e a instrução para resumir (esta chamada pode ser uma Tool interna do agente ou uma chamada direta via MCP Client).
    *   **(Observação 3):** Recebe o resumo com os 3 pontos.
    *   **(Pensamento 4):** Preciso salvar o resumo no arquivo 'artemis_summary.txt'.
    *   **(Ação 4):** Chama a Tool `write_file` (via `mcp-server-filesystem`) com `path='artemis_summary.txt'` e `content=resumo`.
    *   **(Observação 4):** Recebe confirmação de escrita.
    *   **(Pensamento 5):** Tarefa concluída. Preparar resposta final.
5.  **Agente** retorna a resposta final (ex: "Pesquisa concluída, resumo salvo em artemis_summary.txt.") para o **Host**.
6.  **Host** (opcionalmente) chama `tool: apply_personality` no **`mcp-server-personality`**.
7.  **Host** envia a resposta final para a Interface Terminal.

### 3.3 Implementação do Framework de Agentes (no Host - `agents/`)

#### `agents/tools.py`: Wrappers LangChain para Tools MCP

Estes transformam chamadas do agente LangChain em chamadas MCP via os clientes.

```python
# agents/tools.py
from langchain_core.tools import BaseTool, tool
from pydantic import Field, BaseModel
from typing import Type, Any, List

# Importar os MCP Clients necessários
from clients.web import WebClient
from clients.filesystem import FilesystemClient
# ... importar outros clientes

# --- Exemplo: Wrapper para mcp-server-fetch ---
# Inicializar clientes (idealmente via injeção de dependência no AgentExecutor)
web_client = WebClient(settings.FETCH_SERVER_CMD)
filesystem_client = FilesystemClient(settings.FILESYSTEM_SERVER_CMD)

class FetchInput(BaseModel):
    url: str = Field(description="URL da página web a ser buscada.")
    # Adicionar outros args da tool 'fetch' se necessário

@tool(args_schema=FetchInput)
async def search_web_tool(url: str) -> str:
    """Busca o conteúdo de uma página web. Retorna o conteúdo principal como Markdown."""
    # Nota: Gerenciar a conexão do cliente aqui pode ser ineficiente.
    # Idealmente, os clientes são gerenciados no nível do AgentExecutor/Host.
    # Este é um exemplo simplificado.
    async with web_client.connect():
        try:
            # A tool fetch do servidor oficial já retorna markdown
            # A chamada exata ao método do cliente pode variar
            result_list = await web_client.fetch_content(url)
            # Extrair e retornar o texto (pode precisar de parsing)
            if result_list and isinstance(result_list[0], TextContent):
                return result_list[0].text
            return "Erro ao buscar conteúdo."
        except Exception as e:
            return f"Erro ao buscar URL {url}: {e}"

# --- Exemplo: Wrapper para mcp-server-filesystem ---
class WriteFileInput(BaseModel):
    path: str = Field(description="Caminho completo do arquivo para salvar o conteúdo.")
    content: str = Field(description="Conteúdo a ser escrito no arquivo.")

@tool(args_schema=WriteFileInput)
async def write_file_tool(path: str, content: str) -> str:
    """Escreve o conteúdo fornecido em um arquivo no sistema de arquivos local."""
    async with filesystem_client.connect():
        try:
            success = await filesystem_client.write_file(path, content)
            return f"Arquivo salvo com sucesso em {path}." if success else f"Falha ao salvar arquivo em {path}."
        except Exception as e:
            return f"Erro ao escrever arquivo {path}: {e}"

# --- Lista de Ferramentas para o Agente ---
def get_mcp_tools() -> List[BaseTool]:
    """Retorna a lista de ferramentas LangChain baseadas em MCP."""
    return [search_web_tool, write_file_tool] # Adicionar mais wrappers aqui

```

#### `agents/agent_factory.py`: Criação de Agentes

Usa `create_tool_calling_agent` ou outros construtores de agentes LangChain, passando o LLM (via MCP Client) e a lista de `get_mcp_tools()`.

```python
# agents/agent_factory.py
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.language_models.chat_models import BaseChatModel # Para type hint
from typing import List
from .tools import get_mcp_tools # Importa nossos wrappers

# Exemplo de Prompt (pode usar um do Hub)
AGENT_PROMPT = ChatPromptTemplate.from_messages(
    [
        ("system", "Você é um assistente útil com acesso a ferramentas."),
        MessagesPlaceholder(variable_name="chat_history", optional=True),
        ("human", "{input}"),
        MessagesPlaceholder(variable_name="agent_scratchpad"),
    ]
)

def create_mcp_agent_executor(llm: BaseChatModel) -> AgentExecutor:
    """Cria um AgentExecutor que usa ferramentas MCP."""
    tools = get_mcp_tools()
    agent = create_tool_calling_agent(llm, tools, AGENT_PROMPT)
    agent_executor = AgentExecutor(
        agent=agent,
        tools=tools,
        verbose=True # Para depuração
    )
    return agent_executor

```

## 4. Integração da Fase 4 com Fase 3

-   O **Host (`ChatbotApp`)** agora inclui um **`Orchestrator`** (`core/orchestrator.py`) que recebe a entrada primeiro.
-   O `Orchestrator` usa o `RouterInteligente` (ou lógica similar) para decidir se a tarefa é simples (vai para os servidores Ollama/RAG/Memória diretamente via clients) ou complexa (vai para o `AgentFactory`).
-   O `AgentFactory` cria um agente LangChain configurado com:
    *   Um LLM (acessado via MCP Client para `mcp-server-llm-api` ou `mcp-server-ollama`).
    *   Uma lista de `Tools` (os wrappers em `agents/tools.py`) que usam os **MCP Clients** para interagir com **todos** os servidores MCP disponíveis (`filesystem`, `rag`, `ollama`, `memory`, `fetch`, `media`, etc.).
-   O **Host** pode chamar o `mcp-server-personality` para formatar a resposta final do agente ou do roteador.
-   O **Host** ou **Agentes** podem chamar o `mcp-server-metacognition` para análise.

## 7. Riscos e Mitigações (Atualizado)

| Risco                                   | Probabilidade | Impacto | Mitigação                                                                           |
| :-------------------------------------- | :------------ | :------ | :---------------------------------------------------------------------------------- |
| Complexidade do LangChain Agent         | Alta          | Alto    | Começar com agentes simples; Usar LangSmith para debug; Focar em `create_tool_calling_agent`. |
| LLM do Agente não usa Tools MCP bem     | Média         | Alto    | Engenharia de prompt (descrições das tools); Usar LLMs mais capazes (Llama3 70B+). |
| Performance (Múltiplas Chamadas MCP)    | Média         | Médio   | Otimizar tools MCP (batching interno); Cache nos servidores; Monitorar latência.   |
| Gerenciamento de Estado do Agente       | Média         | Médio   | Usar memória via `mcp-server-memory`; Limitar iterações do agente.                  |
| Segurança (Agente executando ações)   | Alta          | Crítico | **Manter confirmação humana (via Host) para tools destrutivas (write_file, etc.)** |

## 8. Conclusão Revisada

A Fase 4 introduz uma camada de inteligência avançada com Agentes LangChain operando sobre a arquitetura MCP estabelecida. As funcionalidades de Web Fetch, Metacognição e Personalidade são encapsuladas em servidores MCP dedicados. O Host agora orquestra não apenas chamadas diretas aos servidores, mas também delega tarefas complexas aos agentes, que por sua vez utilizam as Tools MCP. Esta fase demonstra o poder da arquitetura modular MCP, permitindo a integração complexa de múltiplos sistemas (locais e remotos) de forma organizada e gerenciável.
